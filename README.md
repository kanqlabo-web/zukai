# 図解メーカー

演劇の「図解」（テーマ活動の友・《タイミング》・動き・図・参考写真）をみんなで同時に作り、A4のPDFに書き出すWebツールです。GitHub Pages で公開し、データは Firebase（Google の無料サービス）に保存します。

- ライブラリー → 話 → トラック → 稿（第1稿・第2稿…）の単位で管理
- メンバー一覧（名前・役・キャラクターの表記）はライブラリーごとに1つ。番号は上から順に自動で付き、すべての図解に反映
- テマ友を貼り付け、行をタップすると最初の数語をタイミングにして図解を作成（語句を選んで指定も可）
- 図：番号の丸・楕円・四角・手書きの囲み・矢印・太矢印・文字、白／灰／黒の塗り分け、直前の図の複製
- 参考写真は自動で縮小して保存
- Googleドライブと同じ共有：ライブラリーごとにメールアドレスやGoogleグループで共有、またはリンク共有。権限はオーナー・編集者・閲覧者
- Googleアカウントがあればだれでもログインでき、自分に共有されたライブラリーだけが見える
- パソコン・スマホ・タブレット対応、ほかの人の変更はその場で反映

`js/firebase-config.js` が空のままだと **デモモード** で動きます（データはそのブラウザの中だけ）。まず GitHub Pages で公開して動きを確かめてから、Firebase をつなぐのがおすすめです。

---

## 手順1　GitHub Pages で公開する

1. GitHub にログインし、右上の「＋」→「New repository」。
   - Repository name：例 `zukai`
   - **Public** を選ぶ（無料プランの GitHub Pages は公開リポジトリが必要です）
   - 「Create repository」
2. 作成直後の画面で「uploading an existing file」をクリック。
3. このフォルダの中身（`index.html`、`css`、`js`、`firestore.rules`、`README.md`）をすべてドラッグ＆ドロップし、「Commit changes」。
   - フォルダごとドラッグすると `css/` `js/` の構造が保たれます。`zukai` フォルダ自体ではなく、**中身**を入れてください。
4. リポジトリの「Settings」→ 左の「Pages」。
   - Source：「Deploy from a branch」
   - Branch：`main`、フォルダ：`/ (root)` →「Save」
5. 1〜2分待つと、上部に `https://（ユーザー名）.github.io/zukai/` と表示されます。開くとデモモードで動きます。

## 手順2　Firebase プロジェクトを作る

1. <https://console.firebase.google.com/> を開き、Google アカウントでログイン。
2. 「プロジェクトを作成」→ 名前（例 `zukai`）→ Google アナリティクスは「無効」でOK →「プロジェクトを作成」。
3. プロジェクトの画面で「ウェブ」アイコン（`</>`）→ アプリのニックネーム（例 `zukai-web`）→「アプリを登録」。
   - 「Firebase Hosting も設定する」にはチェックしない
4. 表示される `const firebaseConfig = { ... }` の中身を控えます（apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId）。

## 手順3　設定を貼り付ける

1. GitHub のリポジトリで `js/firebase-config.js` を開き、右上の鉛筆アイコン（Edit）。
2. 空欄の `""` の中に、手順2-4 で控えた値をそれぞれ入れて「Commit changes」。

```js
export const firebaseConfig = {
  apiKey: "AIza…",
  authDomain: "zukai-xxxx.firebaseapp.com",
  projectId: "zukai-xxxx",
  storageBucket: "zukai-xxxx.firebasestorage.app",
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abcdef"
};
```

> apiKey は公開しても問題ない値です（Webアプリの仕組み上、ブラウザに渡ります）。データの保護は次の「ルール」で行います。

## 手順4　ログインとデータベースを有効にする

**Googleログイン**
1. Firebase の左メニュー「構築」→「Authentication」→「始める」。
2. 「Sign-in method」→「Google」→「有効にする」→ サポートメールを選んで「保存」。
3. 「設定」タブ →「承認済みドメイン」→「ドメインを追加」→ `（ユーザー名）.github.io` を追加。

**データベース（Firestore）**
1. 左メニュー「構築」→「Firestore Database」→「データベースを作成」。
2. ロケーション：`asia-northeast1（東京）`、モード：**本番環境モード** →「作成」。
3. 「ルール」タブを開き、中身をすべて消して、このフォルダの `firestore.rules` の内容を貼り付け →「公開」。

## 手順5　ログインして確かめる

1. 公開したURLを開き、「Googleでログイン」。
2. ホームでライブラリーを作ると、あなたがそのライブラリーの「オーナー」になります。
3. ライブラリーページの「共有」から、ほかの人を追加します（使い方の「共有」を参照）。

## 手順6　Googleグループでまとめて共有できるようにする（任意）

共有画面に「〇〇@googlegroups.com」を入れたとき、そのグループのメンバー全員をまとめて追加できるようにします。小さなウィンドウで、**追加しようとしている本人のGoogleアカウント**の権限でグループのメンバー一覧を読むので、だれがどのグループを使っても大丈夫です（本人がメンバー一覧を見られるグループに限ります）。設定は最初に1回だけです。

1. <https://script.google.com/> →「新しいプロジェクト」。左上の名前を「図解グループ確認」などに変えます（以前テストで作ったプロジェクトは使わず、新しく作ってください）。
2. `コード.gs` の中身をすべて消して、このフォルダの `gas/groups-webapp.gs` の内容を貼り付けて保存（Ctrl+S）。
   - `ALLOWED_ORIGIN` はサイトのアドレス（`https://kanqlabo-web.github.io`）のままでOKです。
3. 右上の「デプロイ」→「新しいデプロイ」。歯車アイコンから種類「ウェブアプリ」を選び、次のように設定して「デプロイ」。
   - 次のユーザーとして実行：**ウェブアプリにアクセスしているユーザー**
   - アクセスできるユーザー：**Google アカウントを持つ全員**
4. 許可を求められたら許可します（「Googleで確認されていません」と出たら「詳細」→「〜に移動」）。
5. 表示された「ウェブアプリのURL」（`https://script.google.com/macros/s/…/exec`）をコピーし、`js/settings.js` の `GROUP_LOOKUP_URL = ''` の `''` の中に貼り付けてGitHubに保存します。

使うときは、共有画面でグループのアドレスを入れて「追加」を押すだけです。各自、初めてのときだけGoogleの許可画面が出ます。グループのアドレスで追加したときは、その時点のメンバーが1人ずつ追加されます。あとからグループに入った人は、もう一度グループのアドレスで追加してください（すでに共有されている人は重複しません）。

## 別の公開方法　Firebase Hosting で公開する（GitHub Pages の代わり）

アドレスは `https://zukai-8a392.web.app` になります。無料プランのままで使えます。

1. https://nodejs.org/ から「LTS」版をダウンロードしてインストール（すべて「次へ」でOK）
2. zip を解凍し、`zukai` フォルダを「ドキュメント」などに置く
3. スタートメニューで「cmd」と入力し「コマンド プロンプト」を開く
4. 次を1行ずつ入力して Enter
   ```
   npm install -g firebase-tools
   firebase login
   ```
   ブラウザが開くので、Firebase を作ったGoogleアカウントでログインして許可します
5. `cd ` と入力（cd のあとに半角スペース）し、`zukai` フォルダをコマンドプロンプトの画面にドラッグして Enter
6. 次を入力して Enter
   ```
   firebase deploy --only hosting --project zukai-8a392
   ```
   最後に `Hosting URL: https://zukai-8a392.web.app` と出たら公開完了です
7. ファイルを直したときは、5 と 6 をもう一度行います

## 使い方

1. ホーム上部の欄にライブラリー名を入れて「作成」（「サンプルを作る」でサンプルも試せます）
   - ライブラリーを作った人が、そのライブラリーの「オーナー」になります
2. ライブラリーページの「共有」で、いっしょに作る人を追加します（Googleドライブの共有と同じです）
   - **ユーザーやグループを追加**：メールアドレスを入れて「編集者」「閲覧者」「オーナー」を選び「追加」。`〇〇@googlegroups.com` を入れると、小さなウィンドウでグループを確認して、メンバー全員をまとめて追加します（手順6の設定が必要。初回だけ許可画面が出ます）
   - **一般的なアクセス**：「制限付き」なら追加した人だけ、「リンクを知っている全員」ならリンクを開いてログインした人がだれでも参加できます（閲覧者／編集者を選べます）
   - 「リンクをコピー」で作ったリンクを、LINEやメールで送ってください（追加しても自動では通知されません）
   - 権限：オーナー＝共有の設定・ライブラリーの削除もできる／編集者＝ライブラリーの中身を編集できる／閲覧者＝見ることとPDFの書き出しだけ
   - オーナー以外の人は、共有画面の「共有から抜ける」で自分を外せます
3. 「メンバー一覧」で名前・役・キャラクターの表記（例：ルー、エド）を入力。兼役は役の欄の右の「＋」で追加（CD係の行は役の入力欄なし）
   - 新しいライブラリーには最初からCD係の欄があります。CD係は一覧とPDFの表にだけ載り、図には出ません
   - いらない人は、行の右のゴミ箱で削除できます
   - 番号は上から順に自動で付きます。左の「⠿」をドラッグすると順番を入れ替えられ、図の番号も一緒に変わります
   - 「キャラクターの表記のルール」に表記の決まりをメモしておけます
4. 「＋ 話を追加」「＋ トラックを追加」
5. トラックを開き「テマ友を貼り付け」
   - キャラクター名（PETER: など）は自動で薄い文字になります。判定がずれた行は、その行をタップして「キャラ名ではない」「〜はキャラ名」で直せます
6. テーマ活動の友の行をタップ →「この行に図解を追加」。行の最初の数語が自動でタイミングになります。語句をなぞって選ぶと、その語句をタイミングにできます（あとから書き換えも可）
   - 図解には図が必ず1枚つきます。前に図があれば、その人の位置を引き継ぎます
   - 「＋説明」「＋図」「＋直前の図を複製」「＋写真」で追加できます
   - 文章の ● ☆ ＊ → ボタンで行頭に印をつけられます
   - 「⋯」→「上の段とまとめる」で、ひとつの段に複数の《タイミング》を並べられます
7. 「PDFに書き出す」→「PDFを保存」→ 印刷画面で「PDFに保存」
   - ライブラリーページの「この話をPDFに」で、その話の全トラックを1つのPDFにまとめられます（各トラックの最新稿）
   - iPhone：共有ボタン →「プリント」→ プレビューを2本指で広げる → 共有 →「ファイルに保存」
8. 稿を改めるときは「新しい稿を作る」。前の稿はそのまま残ります。いらない稿は、稿の画面の「⋯」→「この稿を削除」で消せます
9. Word（.docx）で書き出す：稿の画面の「⋯」、またはPDFの画面の「Word」。Googleドキュメントでも開けます
10. 図解PDFの取り込み：ライブラリーページの「図解PDFを取り込む」。Googleドキュメントなどで作った図解のPDFから、テーマ活動の友・タイミング・メモ・メンバー一覧を取り込みます（図は写真として入ります）
11. ホームのライブラリーの「⋯」から、オーナーはライブラリーの削除、それ以外の人は共有の解除ができます

画面では「トラック」、PDFのタイトルなど細かい所では「トラ」と表記します（例：2話図解_トラ1_第1稿）。

### 図の編集のコツ

- 「人」ツール：右の一覧で人を選んで舞台をタップ。続けてタップすると次の番号に進みます。配置済みの人を選んでタップすると、その人を移動します
- 番号の変更：人を選んで右の「番号」を書き換えます。ほかの人と同じ番号にすると、2人を入れ替えます
- 番号なしの人：「人」ツールの「番号なしの人」で置けます。右の「役名」に入れた文字が横に表示されます
- 線：「直線」「曲線」は点を順に押して引きます（最後の点をもう一度押すか Enter で完成）。直線は点の間をまっすぐ（ギザギザも可）、曲線はなめらかにつなぎます。あとから点をドラッグして形を直せます。「手書き線」はなぞった形の線です
- 「残りの人で埋める」：楕円・四角・手書き囲み・線を選んで押すと、まだ置いていない人を図形の中（線なら線に沿って）へ、ほどよく均等に並べます（人数も指定可）。丸が図形から少しはみ出しても入れます。2枚目以降の図では、ひとつ前の図からの移動が最も少なくなるように並べます（「ランダム」にも切り替え可）。図形の名前はよけずに並べ、名前はあとから空いている所に表示されます
- あとの図にも反映：編集画面の上の「あとの図にも反映」をオンにしておくと、背景を動かしたり消したりしたとき、そのあとの図のうち背景がまだ同じままの図にも同じ変更が入ります（人は、あとの図でも同じ位置のままなら一緒に動きます）
- メンバーの自動入れ替え：メンバーを2人以上選ぶと出ます。立ち位置はそのままで番号だけを入れ替えます
  - 身長順：青い矢印の両端をドラッグして向きを決めると、根元「低」から先「高」へ、番号の小さい人（身長の低い人）から順に並びます
  - 最小ストレッチ：ひとつ前の図からの移動がいちばん少なくなる並びにします
- 図形の名前：図形や線・矢印をダブルクリック（スマホはダブルタップ）すると、その場で「森」「台座」などの名前を書けます。人なら役名、文字ならその文字を書き換えます。名前は重ならない位置に表示されます（表示／隠すの切り替え可）
- 役名：メンバー一覧の「キャラクターの表記」が丸の横に出ます。役ごとに表示／隠すを切り替えられます（何も選んでいないときの「役名の表示」、または丸を選んだとき）。兼役の人は、最初の役だけが表示された状態から始まります
- 「選べるもの」：すべて／図形／メンバーを切り替えると、範囲選択やタップでその種類だけを選べます
- 楕円・四角：選択すると角のつまみで大きさ、上のつまみで回転
- パソコン：Ctrl+Z 元に戻す／Ctrl+D 複製／Ctrl+C・Ctrl+V 別の図へコピー／Delete 削除／矢印キーで微調整
- スマホは横向きがおすすめ。「＋」で拡大して「スクロール」で移動

## 無料枠について

Firebase の無料プラン（Spark）で動きます。Firestore は1日あたり 読み取り5万回・書き込み2万回、保存1GBまで無料で、数十人の団体なら通常は十分です。写真は1枚あたり最大約300KBに縮小して保存します。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `index.html` | 入口 |
| `css/app.css` | 画面のデザイン |
| `css/sheet.css` | PDF（A4）のレイアウト |
| `js/firebase-config.js` | Firebase の設定（手順3） |
| `js/app.js` | 起動・ログイン・画面切り替え |
| `js/views-*.js` | 各画面 |
| `js/editor.js` / `js/stage.js` | 図の編集と描画 |
| `js/print.js` | PDF用ページ |
| `js/script.js` | テーマ活動の友の解析（キャラクター名・字下げ・タイミング位置） |
| `js/db*.js` | 保存先（Firebase／デモ） |
| `firestore.rules` | データベースのセキュリティルール（手順4） |
| `js/settings.js` | グループ確認用ウェブアプリのURL（手順6） |
| `gas/` | Googleグループのメンバー一覧を読むウェブアプリ（手順6。サイトには使われません） |

外部ライブラリは使っておらず、ビルド作業も不要です（Firebase は Google の配信サーバーから読み込みます）。
